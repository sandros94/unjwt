# Elysia plugin

> Put a session on every Elysia request context, and guard the routes that need a signed-in visitor.

`unjwt/adapters/elysia` turns a session into an Elysia plugin. Every handler then finds the session on its context as `session`, ready to read, update or clear, and a route can ask for a signed-in visitor with one option. The session behaves as on every other framework: same config, same hooks, same cookies. [Sessions](/sessions) explains what a session is, and [Configure a session](/sessions/configure) every setting.

## Before you start

- Elysia 1.4.29 or later, installed next to `unjwt`. Nothing else: the plugin runs wherever `app.handle(request)` does, Bun, Node.js, Deno and Workers included.
- A session key loaded at start-up, as in [Configure a session](/sessions/configure#make-a-session-key).
- The cookies are called `__Host-elysia-jws` and `__Host-elysia-jwe` unless you set `name`. A `__Host-` cookie needs HTTPS, or `http://localhost` in most browsers.

## Add a session to an app

`jweSession(config)` for an encrypted session, `jwsSession(config)` for a signed one. Both take the [same config](/sessions/configure#options) as `defineJWESession` and `defineJWSSession` from `unjwt/session`:

<!-- automd:region src="../../examples/sessions/elysia-app.ts" -->

```ts [elysia-app.ts]
import { Elysia, t } from "elysia";
import { jweSession } from "unjwt/adapters/elysia";

// const key = the "oct" JWK from SESSION_KEY (see Configure a session)

interface AppSession {
  userId: string;
}

const app = new Elysia()
  .use(jweSession<AppSession, "7D">({ key, maxAge: "7D" }))
  .post(
    "/login",
    async ({ session, body }) => {
      // Check the credentials first, then:
      await session.update({ userId: body.userId });
      return { expiresAt: session.expiresAt };
    },
    { body: t.Object({ userId: t.String() }) },
  )
  .get("/me", ({ session }) => session.data, { requireSession: true })
  .post("/logout", async ({ session }) => {
    await session.clear();
    return { signedOut: true };
  });
```

<!-- /automd -->

- **`session` on the context**: typed by the plugin's type arguments, here `AppSession` and `"7D"`. It is empty until `update()`, and reading it sets no cookie.
- **`requireSession`**: a route with `{ requireSession: true }` answers `401 Unauthorized` when the request carries no valid session, before the handler runs.
- **Writes**: `update()` and `clear()` set the cookie on Elysia's response, with the attributes from [Change cookie attributes](/sessions/configure#change-cookie-attributes).

Call `update()` and `clear()` while Elysia is still building the response: in the handler or in a hook that runs before the response, such as `beforeHandle`. A write from `onAfterResponse` resolves, but its cookie is never sent.

## Run two sessions side by side

`contextKey` sets the name the session gets on the context, and the guard follows it: `contextKey: "api"` gives `ctx.api` and `requireApi`. `defineJWSSession` and `defineJWESession` from `unjwt/adapters/elysia` give you the definition itself, whose `plugin()` is the same plugin and whose `issue()` and `open()` work outside any request:

<!-- automd:region src="../../examples/sessions/elysia-app.ts" name="define" -->

```ts [elysia-app.ts]
import { defineJWSSession } from "unjwt/adapters/elysia";

// const signingKey = an HS256 JWK loaded at start-up

const apiSession = defineJWSSession<{ userId: string; scope: string }, "30D", "api">({
  key: signingKey,
  name: "__Host-api",
  contextKey: "api",
  maxAge: "30D",
  sessionHeader: "authorization",
});

const apiApp = new Elysia()
  .use(apiSession.plugin())
  .get("/api/whoami", ({ api }) => api.data, { requireApi: true });

/** A token for a script or a CLI, minted outside any request. */
export function apiTokenFor(userId: string): Promise<string> {
  return apiSession.issue({ userId, scope: "read" });
}
```

<!-- /automd -->

- **A name each**: give every session its own `name` and `contextKey`. Two plugins on the same `contextKey` overwrite each other on the context, and a JWS and a JWE session under one `name` throw `ERR_SESSION_CONFIG_INVALID` on the first request.
- **A header for scripts**: `sessionHeader: "authorization"` lets a script send the issued token as `Bearer <token>`; a browser still uses the cookie.
- **Third type argument**: without type arguments, `contextKey` types `ctx.api` and `requireApi` on its own. When you pass the data type, add the `contextKey` as the third type argument, as above.

## Open the session yourself

Without the plugin, call the definition's `use()` in your own `resolve`, with Elysia's `cookie` and `request` from the context:

<!-- automd:region src="../../examples/sessions/elysia-app.ts" name="resolve" -->

```ts [elysia-app.ts]
const accountSession = defineJWSSession<{ userId: string }, "1h">({
  key: signingKey,
  name: "__Host-account",
  maxAge: "1h",
});

const accountApp = new Elysia()
  .resolve(async ({ cookie, request }) => ({
    account: await accountSession.use({ cookie, request }),
  }))
  .get("/account", ({ account }) => account.data);
```

<!-- /automd -->

## Hooks on Elysia

[Hooks](/sessions/hooks) work as described there, with one difference: the request travels as `context`, not `event`. It holds the `cookie` and `request` the session was opened with, so a hook can call `use(context)` on another definition. These session hooks are separate from Elysia's own lifecycle hooks, such as `onRequest` and `beforeHandle`.

```ts
jweSession({
  key,
  maxAge: "7D",
  hooks: {
    onError: ({ context, error }) => {
      console.warn("session refused", error.code, context.request.headers.get("user-agent"));
    },
  },
});
```

## When it fails

| Situation                                                | What happens                                                                                                                                                                                                                                               |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A guarded route without a valid session                  | `401 Unauthorized`; the handler does not run.                                                                                                                                                                                                              |
| An expired, tampered or foreign token                    | An empty session, the cookie expired, `onExpire` or `onError` fires.                                                                                                                                                                                       |
| `use()` given a `cookie` that is not Elysia's cookie jar | The first `update()` or `clear()` throws `ERR_SESSION_CONFIG_INVALID`.                                                                                                                                                                                     |
| A configuration error                                    | The codes in [Configure a session](/sessions/configure#when-it-fails): `jwsSession()`, `jweSession()` and `defineJWSSession()` / `defineJWESession()` throw them as the app is built. A key of the right kind that doesn't import fails the first request. |
| `update()` after the response was built                  | Resolves, and the cookie is never sent.                                                                                                                                                                                                                    |

`ERR_SESSION_READONLY_EVENT` never comes from Elysia: its cookies always take a write. [Handle errors](/safety/errors) lists every code.

## Options

Every option of [Configure a session](/sessions/configure#options), with these differences:

| Option       | Default                                       | Notes                                                                                     |
| ------------ | --------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `name`       | `"__Host-elysia-jws"` / `"__Host-elysia-jwe"` | Cookie name; `sessionHeader: true` reads `x-elysia-jwe-session` for the default JWE name. |
| `contextKey` | `"session"`                                   | Context member and guard name: `"api"` gives `ctx.api` and `requireApi`.                  |
