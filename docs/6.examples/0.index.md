# Recipes

> Whole tasks rather than single functions: what to call, in what order, and what to store between calls.

Each page here is one job, written the way you would ship it. Every page shows the complete code, the state you keep between calls, the errors you should expect and what to do with each one, and the reasons behind the choices. The outputs in the comments come from running the code.

::card-group ::card{title="Authenticate requests" icon="i-lucide-log-in" to="/examples/authentication-basics"} Issue a short-lived access token at login and check it on every request with one HMAC key. :: ::card{title="Publish and consume a JWKS" icon="i-lucide-key-round" to="/examples/jwks-endpoint"} Serve your public keys, verify someone else's tokens against theirs, and survive key rotation. :: ::card{title="Rotate refresh tokens" icon="i-lucide-refresh-cw" to="/examples/refresh-token-pattern"} Two cookie sessions on H3: a signed access token for minutes, an encrypted refresh token for days, with reuse detection. :: ::card{title="Encrypt end to end" icon="i-lucide-lock" to="/examples/end-to-end-encryption"} Sign, then encrypt to the recipient's public key, so only they can read it and they know who wrote it. :: ::card{title="Sign receipts" icon="i-lucide-stamp" to="/examples/signed-receipts"} Several parties sign the same payload, and the verifier decides which signatures it needs. :: ::
