# Encrypt end to end

> Alice writes a message that only Bob can read, and Bob can prove Alice wrote it.

## The job

In an end-to-end encrypted system the server relays messages it cannot read. Each person holds private keys on their own device and publishes the public halves. To send, Alice encrypts to Bob's public key; only Bob's private key opens it.

Encryption alone does not say who wrote the message. Anyone with Bob's public key, which is everyone, can encrypt to Bob. So Alice first **signs** the message with her own key, then **encrypts** the signed token to Bob. This is a nested JWT ([RFC 7519 §5.2](https://www.rfc-editor.org/rfc/rfc7519#section-5.2)): a JWS inside a JWE.

## Identities

Each person needs two key pairs: one to sign (`Ed25519`) and one to receive (`ECDH-ES+A256KW` on `X25519`). Create them once per device and publish the public halves through your directory.

```ts [identity.ts]
import { generateJWK, type JWKSet } from "unjwt/jwk";

export async function createIdentity(id: string) {
  const signing = await generateJWK("Ed25519");
  const encryption = await generateJWK("ECDH-ES+A256KW", { namedCurve: "X25519" });
  return {
    id,
    privateKeys: { signing: signing.privateKey, encryption: encryption.privateKey },
    publicKeys: { signing: signing.publicKey, encryption: encryption.publicKey },
  };
}
export type Identity = Awaited<ReturnType<typeof createIdentity>>;
export type Contact = { id: string } & Identity["publicKeys"];

export const contacts = new Map<string, Contact>();
export const contactsBySigningKid = new Map<string, Contact>();
export const contactSigningKeys: JWKSet = { keys: [] };

export function addContact(contact: Contact): void {
  contacts.set(contact.id, contact);
  contactsBySigningKid.set(contact.signing.kid, contact);
  contactSigningKeys.keys.push(contact.signing);
}
```

```ts
bob.publicKeys.encryption;
// { kty: "OKP", crv: "X25519", x: "UkTZBFQCpudL…",
//   alg: "ECDH-ES+A256KW", kid: "O-ztspn8Fb4O…" }
```

## Seal and open

```ts [messages.ts]
import { sign, verify } from "unjwt/jws";
import {
  decrypt,
  decryptMulti,
  encrypt,
  encryptMulti,
  type JWEGeneralSerialization,
} from "unjwt/jwe";
import { contacts, contactSigningKeys, contactsBySigningKid, type Identity } from "./identity";

type Message = { iss: string; aud: string | string[]; jti: string; body: string };

export async function sealMessage(from: Identity, to: string, body: string): Promise<string> {
  const recipient = contacts.get(to);
  if (!recipient) throw new Error(`Unknown contact: ${to}`);
  const signed = await signMessage(from, to, body);
  return encrypt(signed, recipient.encryption, { protectedHeader: { cty: "JWT" } });
}

export async function openMessage(me: Identity, token: string) {
  const { payload: signed, protectedHeader } = await decrypt(token, me.privateKeys.encryption, {
    payload: "string",
    algorithms: ["ECDH-ES+A256KW"],
    encryptionAlgorithms: ["A256GCM"],
  });
  if (protectedHeader.cty !== "JWT") throw new Error("Not a nested JWT");
  return verifyMessage(me, signed);
}

function signMessage(from: Identity, to: string | string[], body: string): Promise<string> {
  return sign({ iss: from.id, aud: to, jti: crypto.randomUUID(), body }, from.privateKeys.signing, {
    expiresIn: "7D",
    protectedHeader: { typ: "message+jwt" },
  });
}

async function verifyMessage(me: Identity, signed: string) {
  const { payload, protectedHeader } = await verify<Message>(signed, contactSigningKeys, {
    algorithms: ["Ed25519"],
    typ: "message+jwt",
    audience: me.id,
    requiredClaims: ["iss", "jti", "exp"],
  });
  const sender = contactsBySigningKid.get(protectedHeader.kid ?? "");
  if (!sender || sender.id !== payload.iss) throw new Error("Sender does not own the signing key");
  return { from: sender.id, id: payload.jti, body: payload.body };
}
```

```ts
const token = await sealMessage(alice, "bob", "Meeting moved to 3pm.");
// "eyJraWQiOiJPLXp0c3Bu…", five segments of 252, 54, 16, 520 and 22 characters
// outer header: { kid: "O-ztspn8Fb4O…", cty: "JWT", epk: { kty: "OKP", crv: "X25519", x: "iY1ao14czs7T…" },
//                 alg: "ECDH-ES+A256KW", enc: "A256GCM" }
await openMessage(bob, token);
// { from: "alice", id: "0a8cba14-3f73-4a21-a056-88ebc2d7f589", body: "Meeting moved to 3pm." }
```

[`encrypt()`](/jwt/jwe/encrypt) infers `alg` from the key and defaults `enc` to `A256GCM`. It generates a fresh ephemeral key pair per message, derives the wrapping key from it and Bob's public key, and puts the ephemeral public key in the header as `epk`. [`decrypt()`](/jwt/jwe/decrypt) with `payload: "string"` returns the inner token as text for [`verify()`](/jwt/jws/verify).

## Several recipients

For a group, encrypt the content once and wrap the content key for each member with [`encryptMulti()`](/jwt/jwe/multi):

```ts [messages.ts]
export async function sealGroupMessage(from: Identity, to: string[], body: string) {
  const recipients = to.map((id) => {
    const contact = contacts.get(id);
    if (!contact) throw new Error(`Unknown contact: ${id}`);
    return { key: contact.encryption };
  });
  const signed = await signMessage(from, to, body);
  return encryptMulti(signed, recipients, { protectedHeader: { cty: "JWT" } });
}

export async function openGroupMessage(me: Identity, jwe: JWEGeneralSerialization) {
  const { payload: signed, protectedHeader } = await decryptMulti(jwe, me.privateKeys.encryption, {
    payload: "string",
    algorithms: ["ECDH-ES+A256KW"],
    encryptionAlgorithms: ["A256GCM"],
    strictRecipientMatch: true,
  });
  if (protectedHeader.cty !== "JWT") throw new Error("Not a nested JWT");
  return verifyMessage(me, signed);
}
```

```ts
const group = await sealGroupMessage(alice, ["bob", "carol"], "Draft attached.");
// keys: protected, recipients (2), iv, ciphertext, tag; 1160 bytes as JSON
// protected: { cty: "JWT", enc: "A256GCM" }
// recipients[1].header: { kid: "O3FHVazNJS_H…", epk: { kty: "OKP", crv: "X25519", x: "CN6wDCAvUT3z…" },
//                         alg: "ECDH-ES+A256KW" }
await openGroupMessage(carol, JSON.parse(JSON.stringify(group)));
// { from: "alice", id: "7662b637-aa9d-49a6-a36b-70dda2978699", body: "Draft attached." }
```

## What to store

- **Each device:** its own two private keys, in the platform keychain or a non-exportable store. They never leave the device.
- **The directory:** each person's two public keys, keyed by id. Devices cache their contacts' entries.
- **The server:** the sealed tokens, in transit or at rest. It has nothing that opens them.
- **Optionally, each device:** the `jti` of messages already shown, to drop a relayed duplicate.

## When it fails

| Case                                                | `code`                          | `message`                                                                   |
| --------------------------------------------------- | ------------------------------- | --------------------------------------------------------------------------- |
| Not your message, or the ciphertext was altered     | `ERR_JWE_DECRYPTION_FAILED`     | `JWE decryption failed.` (altered ciphertext: `JWE Decryption Failed`)      |
| Your key is on another curve than the token's `epk` | `ERR_JWE_INVALID`               | `Invalid JWE: "epk" curve "X25519" does not match recipient curve "P-256".` |
| Group message with no entry for your key            | `ERR_JWE_NO_MATCHING_RECIPIENT` | `No recipient matched the provided key under strictRecipientMatch.`         |
| Signed by someone not in your contacts              | `ERR_JWK_KEY_NOT_FOUND`         | `No key found in JWK Set with kid "4KxFGNw4YSG7…".`                         |
| Encrypted to you but never signed                   | `ERR_JWS_INVALID`               | `Invalid JWS: Must contain three parts separated by dots.`                  |
| Bob re-encrypts Alice's message to Carol            | `ERR_JWT_CLAIM_INVALID`         | `Invalid JWT "aud": expected carol, got bob`                                |
| Alice signs with her key but claims `iss: "carol"`  | none, plain `Error`             | `Sender does not own the signing key`                                       |

Show none of these as a message. Drop the token, and surface "a message could not be opened" only when the transport says it was meant for this device.

## Why these choices

- **Sign, then encrypt.** The outer JWE gives confidentiality; the inner JWS gives authorship. [RFC 7519 §11.2](https://www.rfc-editor.org/rfc/rfc7519#section-11.2) recommends this order. In a group message every member holds the content key and could re-encrypt altered content to the others, so only the inner signature tells them what Alice wrote.
- **`aud` inside the signature.** Without it, Bob could forward Alice's signed message to Carol and it would look as if Alice wrote to Carol. `audience: me.id` refuses it.
- **Sender bound to key.** `iss` is a claim the signer writes. The code accepts it only when it names the owner of the key that verified the signature.
- **`cty: "JWT"`.** [RFC 7519 §5.2](https://www.rfc-editor.org/rfc/rfc7519#section-5.2) asks for it on nested tokens; the reader checks it before treating the content as a JWS.
- **Allow-lists on both layers.** `algorithms`, `encryptionAlgorithms` and the signing `algorithms` fix what each layer may use ([RFC 8725 §3.1](https://www.rfc-editor.org/rfc/rfc8725#section-3.1)). `typ: "message+jwt"` keeps any other token signed by the same key out ([RFC 8725 §3.11](https://www.rfc-editor.org/rfc/rfc8725#section-3.11)).
- **ECDH-ES with key wrapping.** The ephemeral key is new per message and discarded after use ([RFC 7518 §4.6](https://www.rfc-editor.org/rfc/rfc7518#section-4.6)), so a later leak of the sender's keys reveals nothing. A leak of Bob's private key does open everything sent to it: rotate receiving keys and publish the new `kid`. The `+A256KW` variant lets the same key serve one recipient and many.

::warning
None of this helps if the directory hands Alice an attacker's key for Bob. Deliver public keys over an authenticated channel and let people compare thumbprints out of band.
::
