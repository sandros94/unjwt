# Introduction

> unjwt signs, verifies, encrypts and decrypts JSON Web Tokens, manages the keys behind them, and keeps sessions in a cookie, on the Web Crypto API with no dependencies.

`unjwt` is a TypeScript library for JSON Web Tokens. It signs tokens so you can trust them when they come back ([JWS](/jws)), encrypts them so nobody else can read them ([JWE](/jwe)), and generates, imports and rotates the keys both need ([JWK](/jwk)). On top of that it keeps a user's session in a cookie or a header, and creates and checks [DPoP](/dpop) proofs that bind a token to the client holding it.

Everything runs on the [Web Crypto API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API), so the same code works in Node.js, Bun, Deno, Cloudflare Workers and browsers, and the package pulls in no other dependencies. If "signed" and "encrypted" still blur together for you, start with [Concepts](/getting-started/concepts).

## The rules that hold everywhere

A few rules run through every module, so you can count on them on every page:

- **One error class**: whatever goes wrong, a bad token or a mistake in your setup, you get a [`JWTError`](/safety/errors) with a `code` such as `ERR_JWT_EXPIRED`. Branch on the code, never on the message. The base64url helpers in `unjwt/utils` are the one exception: they throw an `UnsecureError`, also exported from `unjwt/error`.
- **Keys pick algorithms**: a JWK names its own algorithm, so `sign` and `encrypt` read it from the key and `verify` and `decrypt` accept only that one. A key that names none needs the algorithm spelled out.
- **Limits fail closed**: every call that reads a token bounds its work, such as how many signatures it checks or keys it tries. Past a limit the call refuses the token, it never quietly checks less. [Limits](/safety/limits) lists them.
- **A bad token throws**: `verify` and `decrypt` either return the whole result or throw. You never get a payload whose signature or claims weren't checked.

## What it doesn't do

`unjwt` works on tokens and keys and leaves the rest of the app to you. It has no HTTP client or server, so fetching a remote JWK Set or answering a request is your code. It stores nothing: revocation lists, replay records and refresh-token tables live in your database. It isn't an OAuth or OpenID Connect server, though it signs and checks the tokens one issues. And it doesn't hash passwords; [unsecure](https://unsecure.s94.dev) does that, and it is meant to be used alongside this library.
