# Install unjwt

> Add unjwt to a project, import each module from its own path, and know which types to reach for.

`unjwt` lives on npm as [`unjwt`](https://npmx.dev/package/unjwt). It ships as ES modules with TypeScript types included, and each module has its own import path, so you load only what you use.

## Before you start

A quick check of your setup saves a confusing error later:

- **Node.js**: Node.js 22 or later.
- **Other runtimes**: Bun, Deno, Cloudflare Workers and browsers work when they expose the Web Crypto API as the global `crypto`.
- **Browsers**: Web Crypto's `crypto.subtle` exists only on HTTPS pages and on `localhost`. On a plain HTTP page, nothing that signs, verifies, encrypts or generates keys works.
- **TypeScript**: 5.7 or later, with `"DOM"` or `"WebWorker"` in `compilerOptions.lib`, because the types name `CryptoKey`, `Request` and `Headers`.
- **ES modules only**: the package has no CommonJS build.
- **No runtime dependencies**: installing `unjwt` adds one package to your lockfile. The Elysia plugin is the one exception; it needs `elysia` 1.4.29 or later, which your Elysia app already has.

## Install the package

Pick the line for the package manager your project already uses:

<!-- automd:pm-i name="unjwt" -->

```sh
# ✨ Auto-detect
npx nypm install unjwt

# npm
npm install unjwt

# yarn
yarn add unjwt

# pnpm
pnpm add unjwt

# bun
bun install unjwt

# deno
deno install npm:unjwt
```

## Import a module

Import each function from the path of its module, so every import line says which part of the library it needs:

```ts
import { sign, verify } from "unjwt/jws";
import { generateJWK } from "unjwt/jwk";
import { isJWTError } from "unjwt/error";
```

The package exports these paths:

| Import from             | What it holds                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| `unjwt`                 | Everything from `unjwt/jws`, `unjwt/jwe`, `unjwt/jwk`, `unjwt/utils` and `unjwt/error`, plus every type |
| `unjwt/jws`             | `sign`, `verify` and the multi-signature functions                                                      |
| `unjwt/jwe`             | `encrypt`, `decrypt` and the multi-recipient functions                                                  |
| `unjwt/jwk`             | Generating, importing, exporting, wrapping and deriving keys, and JWK Sets                              |
| `unjwt/utils`           | The base64url codec, type guards, claim checks and random bytes                                         |
| `unjwt/error`           | `JWTError`, `isJWTError` and the error code types                                                       |
| `unjwt/session`         | `defineJWSSession`, `defineJWESession` and the driver API                                               |
| `unjwt/dpop`            | `createDPoPProof` and `verifyDPoPProof`                                                                 |
| `unjwt/adapters/elysia` | The `jwsSession` and `jweSession` Elysia plugins                                                        |

A bundler trims an import from `unjwt` down to what you call, so the root works fine in an app you build. Without a build step, each path loads only its own module; [Use unjwt from a CDN](/examples/cdn-import) shows a page that does that.

## Use the types

The types come in the box, so there's no `@types/unjwt` to install. Every type is exported from `unjwt`, and a few of them show up all over the API:

- **`JWK`** and **`JWKSet`**: a key as JSON, and `{ keys: JWK[] }`. See [Keys](/jwk).
- **`JWTClaims`**: the registered claims (`iss`, `sub`, `aud`, `exp`, `nbf`, `iat`, `jti`) plus any member of your own. Extend it for your claims and pass it as `verify<MyClaims>(…)`.
- **`JWTError`** and **`KnownJWTErrorCode`**: the one error class, and the union of every `code` it can carry. Import both from `unjwt/error`; [Handle errors](/safety/errors) explains each code.
- **`SessionConfigJWS`** and **`SessionConfigJWE`**: the config of a signed or an encrypted session, from `unjwt/session`. See [Configure a session](/sessions/configure).

```ts
import type { JWK, JWKSet, JWTClaims } from "unjwt";
import type { KnownJWTErrorCode } from "unjwt/error";
import type { SessionConfigJWS } from "unjwt/session";
```

## When it fails

These setup mistakes show up as errors rather than as wrong results:

| Situation                                                                      | What happens                                                                                                                                                                        |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An import names a path the package doesn't export, such as `unjwt/adapters/h3` | Node.js throws `ERR_PACKAGE_PATH_NOT_EXPORTED` and bundlers fail to resolve the import. The table above lists every path; sessions on h3, Nitro and Nuxt come from `unjwt/session`. |
| A browser page served over plain HTTP                                          | Generating keys throws a `TypeError`, and signing or verifying throws a `JWTError`, because `crypto.subtle` is missing. Serve the page over HTTPS or from `localhost`.              |
| `unjwt/adapters/elysia` imported without `elysia` installed                    | The import fails with `ERR_MODULE_NOT_FOUND` for `elysia`. Install Elysia, or use `unjwt/session`, which needs no framework.                                                        |
| TypeScript older than 5.7                                                      | `tsc` reports `Type 'Uint8Array' is not generic` inside the package's types. Upgrade TypeScript.                                                                                    |
| `compilerOptions.lib` without `"DOM"` or `"WebWorker"`                         | `tsc` reports `Cannot find name 'Headers'` or `'CryptoKey'` inside the package's types. Add one of the two.                                                                         |
