# JWE

> A JSON Web Encryption token hides its payload from everyone but the holder of the right key, and fails to open if anyone changed it.

::note **ELI5.** Encryption puts the claims in a locked box. Every token gets a fresh random key for the box, called the content encryption key. That key is then itself locked for the recipient: wrapped with a shared secret, with the recipient's public key, or with a key derived from a password. The recipient unlocks the small key first, then the box. The box also carries a seal, so any change to the token makes opening it fail. Nothing inside is readable on the way, which is the difference from a signed token. ::

::card-group ::card{title="encrypt()" icon="i-lucide-lock-keyhole" to="/jwt/jwe/encrypt"} Turn a payload and a key or password into a compact token. :: ::card{title="decrypt()" icon="i-lucide-lock-open" to="/jwt/jwe/decrypt"} Open the token, validate its header and claims, and get the payload back. :: ::card{title="Multi-recipient" icon="i-lucide-users" to="/jwt/jwe/multi"} `encryptMulti()` and `decryptMulti()`: one ciphertext, several recipients. :: ::card{title="Algorithms" icon="i-lucide-list" to="/jwt/jwe/algorithms"} Key management (`alg`) and content encryption (`enc`) tables, with defaults and limits. :: ::

## Two algorithms per token

A JWE header names two algorithms:

- **`alg`** (key management) says how the content key reaches the recipient: `dir`, `A256KW`, `A256GCMKW`, `RSA-OAEP-256`, `ECDH-ES+A256KW`, `PBES2-HS256+A128KW` and their siblings.
- **`enc`** (content encryption) says how the payload is sealed with that key: `A256GCM` by default, or one of the other AES-GCM and AES-CBC-HMAC modes.

`encrypt` reads `alg` from the key when it can and uses `A256GCM` for `enc` unless the key or the options name another.

## Which key do I want

| Situation                                              | Key and `alg`                                       |
| ------------------------------------------------------ | --------------------------------------------------- |
| Your own server encrypts and decrypts (cookies, state) | `generateJWK("A256KW")`, or a CEK with `dir`        |
| Many senders, one receiver who publishes a public key  | `generateJWK("ECDH-ES+A256KW")` or `"RSA-OAEP-256"` |
| A human types the secret                               | a password string, which selects PBES2              |
| One ciphertext for several receivers                   | [`encryptMulti`](/jwt/jwe/multi)                    |

## How they fit together

```ts
import { encrypt, decrypt } from "unjwt/jwe";
import { generateJWK } from "unjwt/jwk";

// A password: PBES2 key derivation, then AES key wrap
const sealed = await encrypt(
  { sub: "user_1", email: "ada@example.com" },
  "correct horse battery staple",
);
const { payload, protectedHeader } = await decrypt(sealed, "correct horse battery staple");
// payload: { sub: "user_1", email: "ada@example.com" }
// protectedHeader: { p2c: 600000, p2s: "CnUYw2xK…", alg: "PBES2-HS256+A128KW", enc: "A256GCM", typ: "JWT" }

// A key pair: anyone with the public key encrypts, only the private key opens
const { publicKey, privateKey } = await generateJWK("RSA-OAEP-256");
const token = await encrypt({ sub: "user_1" }, publicKey, { expiresIn: "1h" });
const result = await decrypt(token, privateKey);
// result.payload: { sub: "user_1", iat: 1792068936, exp: 1792072536 }
// result.protectedHeader: { kid: "DVxklHUn…", alg: "RSA-OAEP-256", enc: "A256GCM", typ: "JWT" }
```

## What encryption does not do

- **It does not say who sent it** when the key is public. Anyone holding the public key can make a valid token. [Sign, then encrypt](/jwt#sign-then-encrypt) when the sender matters.
- **It does not hide the header.** `alg`, `enc`, `kid`, `typ` and any member you add are readable base64url.
- **It does not compress.** A token carrying `zip` is refused on both sides.

## What the library refuses

- `alg: "none"` and algorithms outside the [tables](/jwt/jwe/algorithms), such as `RSA1_5`, before any key work.
- A string key under any `alg` other than PBES2.
- A PBES2 iteration count outside 1000 to 600,000 by default, and a salt under 8 bytes.
- `dir` and bare `ECDH-ES` in a multi-recipient token.
- An ECDH-ES ephemeral key on another curve than the recipient key, and party info over 1024 bytes.

Each refusal is a [`JWTError`](/errors) with a stable `code`, listed on the function pages.
