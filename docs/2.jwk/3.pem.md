# importPEM() / exportPEM()

> Convert between PEM text, the `-----BEGIN …-----` format OpenSSL and most key tools use, and JWKs.

```ts
import { importPEM, exportPEM } from "unjwt/jwk";

const privateJwk = await importPEM(process.env.SIGNING_KEY_PEM!, "ES256", {
  jwkParams: { kid: "ec-1" },
});
// { kty: "EC", x: "AsQftyL9…", y: "a1V6thmo…", crv: "P-256", d: "x4JlYWC6…",
//   kid: "ec-1", alg: "ES256" }

await exportPEM(privateJwk);
// "-----BEGIN PRIVATE KEY-----\nMIGHAgEAMBMGByqGSM49AgEGCCqGSM49AwEHBG0wawIBAQQgx4JlYWC6wRukyvZ4…"
```

PEM carries no algorithm, so `importPEM` always takes one. The result is a JWK with that `alg` stamped on it, ready for [`sign()`](/jwt/jws/sign), [`verify()`](/jwt/jws/verify) or a [JWK Set](/jwk/sets).

## Signatures

```ts
function importPEM<Alg extends JWKPEMAlgorithm, Type extends PEMType | undefined = undefined>(
  pem: string,
  alg: Alg,
  options?: {
    pemType?: Type;
    jwkParams?: {
      "kid"?: string;
      "use"?: string;
      "x5c"?: string[];
      "x5t"?: string;
      "x5t#S256"?: string;
      "x5u"?: string;
    };
  },
): Promise<ImportedPEMJWK<Alg, Type>>;

type PEMType = "pkcs8" | "spki" | "x509";

function exportPEM(
  jwk: JWK,
  options?: { pemFormat?: "pkcs8" | "spki"; alg?: JWKPEMAlgorithm },
): Promise<string>;
```

`JWKPEMAlgorithm` is every asymmetric algorithm: `RS*`, `PS*`, `RSA-OAEP*`, `ES*`, `ECDH-ES*`, `Ed25519` and `EdDSA`. Symmetric keys have no PEM form.

The result type follows `alg` and `pemType`. `alg` picks the family (`"RS256"` gives an RSA JWK, `"ES256"` an EC one, `"EdDSA"` an OKP one) with that `alg` as a literal. `pemType: "pkcs8"` gives the private JWK, `"spki"` or `"x509"` the public one; when the type is read from the label, the result is the union of both and `isPrivateJWK` tells them apart.

```ts
const signer = await importPEM(pkcs8, "ES256", { pemType: "pkcs8" }); // JWK_EC_Private<"ES256">
const verifier = await importPEM(spki, "ES256", { pemType: "spki" }); // JWK_EC_Public<"ES256">
const either = await importPEM(pem, "RS256"); // JWK_RSA_Public<"RS256"> | JWK_RSA_Private<"RS256">
```

## Options

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `pemType` | `"pkcs8" \| "spki" \| "x509"` | read from the label | `importPEM` only. Forces the format, which must still match the label, and types the result as private (`pkcs8`) or public. |
| `jwkParams` | JWK metadata | none | `importPEM` only. Merged onto the result. `alg`, `kty`, `key_ops`, `ext` and key-material members throw `ERR_INVALID_OPTION`. |
| `pemFormat` | `"pkcs8" \| "spki"` | `"pkcs8"` when the JWK has `d`, else `"spki"` | `exportPEM` only. |
| `alg` | `JWKPEMAlgorithm` | the JWK's `alg` | `exportPEM` only. Needed when the JWK has no `alg`. |

## Supported labels

| Label | Format | `importPEM` gives | `exportPEM` writes it |
| --- | --- | --- | --- |
| `-----BEGIN PRIVATE KEY-----` | PKCS#8 | a private JWK | yes, for a JWK with `d` |
| `-----BEGIN PUBLIC KEY-----` | SPKI | a public JWK | yes, for a JWK without `d` |
| `-----BEGIN CERTIFICATE-----` | X.509 | the certificate's public key as a JWK | no |

Only the key is kept from a certificate. Its subject, issuer, dates and signature are not read or checked, so `importPEM` is no substitute for certificate validation. `exportPEM` does not write certificates, because a certificate needs metadata and a CA signature that a JWK cannot supply.

Legacy labels such as `RSA PRIVATE KEY` (PKCS#1) and `EC PRIVATE KEY` (SEC1) are not read, and forcing `pemType` does not change that (the label must still match). Convert them to PKCS#8 first:

```sh
openssl pkcs8 -topk8 -nocrypt -in legacy.pem -out key.pem
```

```ts
await importPEM(pkcs1Text, "RS256");
// JWTError ERR_JWK_INVALID: Cannot infer PEM type from the input, pass "pemType".
```

The input must hold exactly one armoured block. Text before it is ignored ([RFC 7468 §2](https://www.rfc-editor.org/rfc/rfc7468#section-2)); anything but whitespace after it, including a second block, is refused instead of silently importing the first key.

## The `alg` parameter

The algorithm decides how the key body is read. A key that cannot serve it is refused:

```ts
await importPEM(ecPrivatePem, "RS256");
// JWTError ERR_JWK_INVALID: Invalid PEM: the body could not be imported as "RS256".

await importPEM(p256PrivatePem, "ES384");
// JWTError ERR_JWK_INVALID: Invalid PEM: the body could not be imported as "ES384".

await importPEM(ecPrivatePem, "HS256");
// JWTError ERR_JWK_UNSUPPORTED: Invalid or unsupported "alg" value
```

For EC keys under `ECDH-ES*` the curve comes from the key body, and an X25519 key becomes an `OKP` JWK. `Ed25519` and `EdDSA` read Ed25519 keys only.

## Round trips

A certificate, its public key and its private key all describe one key, and the JWKs agree:

```ts
import { readFile } from "node:fs/promises";
import { importPEM, exportPEM } from "unjwt/jwk";
import { sign, verify } from "unjwt/jws";

const privateJwk = await importPEM(await readFile("ec.pem", "utf8"), "ES256", {
  jwkParams: { kid: "ec-1" },
});
const certJwk = await importPEM(await readFile("ec.crt", "utf8"), "ES256");
certJwk.x === privateJwk.x; // true

const token = await sign({ sub: "u1" }, privateJwk);
const { payload } = await verify(token, certJwk);
// { sub: "u1" }

const publicJwk = await importPEM(await readFile("ec.pub.pem", "utf8"), "ES256");
const pem = await exportPEM(publicJwk);
// "-----BEGIN PUBLIC KEY-----\nMFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAEAsQftyL9+V4BcQcgu0C+PjywD0/Y\n…"
pem.trim() === (await readFile("ec.pub.pem", "utf8")).trim(); // true
```

The private key round trips the same way through PKCS#8. `exportPEM` writes 64-character lines between the labels.

`importPEM` returns the key material as a plain JavaScript object. For a private key that should not stay readable, pass the JWK to [`importKey()`](/jwk/import-export), which returns a non-extractable `CryptoKey`, and drop the JWK.

`exportPEM` checks that the format matches the key. Asking for SPKI from a private JWK is refused instead of silently dropping `d`:

```ts
await exportPEM(privateRsaJwk, { pemFormat: "spki" });
// JWTError ERR_JWK_INVALID: Private JWK passed where a public key is expected. Strip `d` (and CRT fields on RSA) before import.
```

## Errors

| Cause | `code` |
| --- | --- |
| No recognised label and no `pemType` | `ERR_JWK_INVALID` |
| A label that differs from `pemType`, more than one block, or trailing data | `ERR_JWK_INVALID` |
| A body that cannot be decoded, or a key the `alg` cannot use | `ERR_JWK_INVALID` |
| `exportPEM` on a JWK with no `alg` and no `alg` option | `ERR_JWK_INVALID` |
| A `pemFormat` that contradicts the key half | `ERR_JWK_INVALID` |
| An `alg` with no PEM form, an unknown `pemType`, or an `oct` JWK | `ERR_JWK_UNSUPPORTED` |
| `pem` that is not a string, or a reserved member in `jwkParams` | `ERR_INVALID_OPTION` |
