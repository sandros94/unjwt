# Import cache

> Turning an RSA, EC or OKP JWK into a `CryptoKey` costs a Web Crypto import. unjwt remembers the result per JWK object, and you can replace or switch off that memory.

```ts
import { generateJWK, importKey } from "unjwt/jwk";

const { publicKey } = await generateJWK("ES256");

(await importKey(publicKey)) === (await importKey(publicKey)); // true, the second call is a cache hit
(await importKey(publicKey)) === (await importKey({ ...publicKey })); // false, a copy is a new object
```

## Signatures

```ts
interface JWKCacheAdapter {
  get(jwk: JWK, alg: JWKAlgorithm): CryptoKey | undefined | Promise<CryptoKey | undefined>;
  set(jwk: JWK, alg: JWKAlgorithm, key: CryptoKey): void | Promise<void>;
}

class WeakMapJWKCache implements JWKCacheAdapter {}

function configureJWKCache(cache: JWKCacheAdapter | false): void;
function clearJWKCache(): void;
```

## What is cached

Every [`importKey()`](/jwk/import-export) of an RSA, EC or OKP JWK goes through the cache, and so do [`sign()`](/jwt/jws/sign), [`verify()`](/jwt/jws/verify), [`encrypt()`](/jwt/jwe/encrypt) and [`decrypt()`](/jwt/jwe/decrypt), which call it. The entry is keyed by the JWK and the algorithm it was imported under.

Two kinds of import skip the cache:

- `oct` JWKs. `importKey` returns their raw bytes, so there is nothing to cache.
- An `importKey` call that passes `extractable` explicitly. The cached key may have been imported with a different setting.

A counting adapter shows the traffic. Two HMAC signatures, one ES256 signature and two verifications produce:

```ts
// await sign({}, hmacJwk); await sign({}, hmacJwk);
// const t = await sign({}, privateKey);
// await verify(t, publicKey); await verify(t, publicKey);
["get EC ES256 miss", "set EC ES256", "get EC ES256 miss", "set EC ES256", "get EC ES256 hit"];
```

## The default: WeakMapJWKCache

The default cache is a `WeakMap` keyed by the JWK object itself. It needs no configuration, and an entry drops when its JWK object is garbage-collected, so there is no eviction to tune. The consequences follow from keying on the object:

- A hit needs the same object. A spread copy, or a JWK parsed again from JSON, is a miss. Keep one object per key and pass that reference around.
- A JWK object is treated as immutable once it has been imported. Changing its members in place keeps serving the old `CryptoKey`.

```ts
const config = { verifyKey: { ...oldKey.publicKey } };
await verify(oldToken, config.verifyKey); // imports and caches under this object

Object.assign(config.verifyKey, newKey.publicKey); // same object, old CryptoKey still cached
await verify(newToken, config.verifyKey);
// JWTError ERR_JWS_SIGNATURE_INVALID

config.verifyKey = { ...newKey.publicKey }; // a new object: imported fresh
await verify(newToken, config.verifyKey); // { payload: { sub: "u1" }, … }
```

Rotate by replacing the object, never by editing it.

## Replacing the cache

`configureJWKCache(adapter)` installs any object with `get` and `set`. Both may return promises, so a store shared across workers works too. The adapter is in charge of its own eviction.

When the cache outlives JWK object identity, key it on the key material: the [RFC 7638 thumbprint](/jwk/generate#the-default-kid-is-a-thumbprint), plus which half of the pair it is, plus the algorithm.

```ts
import { configureJWKCache, importKey, thumbprint } from "unjwt/jwk";
import type { JWK, JWKAlgorithm } from "unjwt/jwk";

const cacheKey = async (jwk: JWK, alg: JWKAlgorithm) =>
  `${await thumbprint(jwk)}:${"d" in jwk ? "private" : "public"}:${alg}`;

const map = new Map<string, CryptoKey>();
configureJWKCache({
  get: async (jwk, alg) => map.get(await cacheKey(jwk, alg)),
  set: async (jwk, alg, key) => {
    map.set(await cacheKey(jwk, alg), key);
  },
});

const fromJson = () => JSON.parse(JSON.stringify(publicKey));
(await importKey(fromJson())) === (await importKey(fromJson())); // true
[...map.keys()]; // ["KoMX1C4E…:public:ES256"]
```

::warning
Include the pair half. A thumbprint covers only the public members ([RFC 7638 §3.2](https://www.rfc-editor.org/rfc/rfc7638#section-3.2)), so a private JWK and its public counterpart share one. Keyed on thumbprint and algorithm alone, `sign()` caches the private key and a later `verify()` with the public JWK is served the private one.
::

::warning
Never key a cache on `kid`. A `kid` is a label its publisher picks, and two different keys can carry the same one, during a rotation or when two sets are merged. A `kid`-keyed entry would then serve the wrong key material.
::

## Disabling and resetting

```ts
import { clearJWKCache, configureJWKCache } from "unjwt/jwk";

configureJWKCache(false); // every import runs again
(await importKey(publicKey)) === (await importKey(publicKey)); // false

clearJWKCache(); // back to a fresh WeakMapJWKCache
(await importKey(publicKey)) === (await importKey(publicKey)); // true
```

`clearJWKCache()` also discards a custom adapter, so call `configureJWKCache` again afterwards if you had one. It is mostly useful in tests, in a `beforeEach`, to keep imports from leaking between cases.

## Errors

The cache functions throw nothing of their own. An error thrown by a custom adapter's `get` or `set` surfaces through the call that triggered it:

| Caller               | What you see                                                                       |
| -------------------- | ---------------------------------------------------------------------------------- |
| `importKey()`        | the adapter's own error, unchanged                                                 |
| `sign()`, `verify()` | `ERR_JWK_INVALID` (`Key is not usable for ES256.`), the adapter's error as `cause` |
| `decrypt()`          | `ERR_JWE_DECRYPTION_FAILED`, the adapter's error as `cause`                        |

Make `get` return `undefined` on a store outage instead of throwing, so the import runs uncached.
