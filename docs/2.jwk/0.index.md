# JWK

> A JSON Web Key is a cryptographic key written as a plain JSON object. Every function in unjwt takes one, and this section covers how to make, convert, protect and organise them.

::note **ELI5.** A key is the secret ingredient that signs or locks a token. Web Crypto hands you keys as opaque `CryptoKey` handles that only live inside one running process. A handle cannot be written to a config file, sent over the network, or pasted into an environment variable. A JWK ([RFC 7517](https://www.rfc-editor.org/rfc/rfc7517)) is the same key spelled out as JSON: its type (`kty`), the algorithm it is meant for (`alg`), a name (`kid`) and the key material itself. Because it is a plain object, you can store it, publish the public half for others to verify with, and hand it straight to [`sign()`](/jwt/jws/sign) or [`encrypt()`](/jwt/jwe/encrypt). unjwt turns it into a `CryptoKey` for you at the moment it is needed. ::

```json
{
  "kty": "EC",
  "crv": "P-256",
  "x": "8b3ZF0WoLhgvkCazLphsW6_JfsA8AMR4uCBOqzqlOcw",
  "y": "NUhlM5soIbCkSMeNW-P97eSjDJyPUJq0goTWWBrjt5c",
  "alg": "ES256",
  "kid": "ATEQ_IO40X5ZWanbK5H6GuDSJKINUGHOPtELd6pQGoM"
}
```

Every function on these pages comes from one subpath:

```ts
import { generateJWK, importKey, exportPEM } from "unjwt/jwk";
```

## The key shapes

The `kty` member decides which other members a key has. A key with a private member (`d` on RSA, EC and OKP) is the private half; the same object without it is the public half. An `oct` key has no halves: whoever holds it can both sign and verify.

| `kty` | What it is | Key members | Algorithms |
| --- | --- | --- | --- |
| `oct` | A shared secret | `k` | `HS*`, `A*KW`, `A*GCMKW`, `A*GCM`, `A*CBC-HS*` |
| `RSA` | An RSA key pair | `n`, `e`, plus `d`, `p`, `q`, `dp`, `dq`, `qi` when private | `RS*`, `PS*`, `RSA-OAEP*` |
| `EC` | An elliptic-curve key pair (P-256, P-384, P-521) | `crv`, `x`, `y`, plus `d` when private | `ES*`, `ECDH-ES*` |
| `OKP` | An Edwards or Montgomery curve key pair (Ed25519, X25519) | `crv`, `x`, plus `d` when private | `Ed25519`, `EdDSA`, `ECDH-ES*` |

The [type guards](/utils/guards) in `unjwt/utils` tell these apart at runtime.

## How they fit together

A key is generated once, used to sign, published as part of a set for verifiers, and converted to PEM when another tool asks for that format.

```ts
import { generateJWK, exportPEM, importPEM } from "unjwt/jwk";
import { sign, verify } from "unjwt/jws";

// 1. Make a key pair. Each half is a plain JSON object.
const { privateKey, publicKey } = await generateJWK("ES256");
// publicKey.kid: "ATEQ_IO40X5ZWanbK5H6GuDSJKINUGHOPtELd6pQGoM"

// 2. Sign with the private half. The token header carries the key's kid.
const token = await sign({ sub: "user-42" }, privateKey);
// "eyJraWQiOiJBVEVRX0lPNDBYNVpXYW…"

// 3. Publish the public half in a JWK Set. Verifiers pick the key by kid.
const jwks = { keys: [publicKey] };
const { payload, protectedHeader } = await verify(token, jwks);
// payload:         { sub: "user-42" }
// protectedHeader: { kid: "ATEQ_IO40X5ZWanbK5H6GuDSJKINUGHOPtELd6pQGoM", alg: "ES256", typ: "JWT" }

// 4. Hand the same key to a tool that wants PEM, and read it back.
const pem = await exportPEM(publicKey); // "-----BEGIN PUBLIC KEY-----\n…"
const again = await importPEM(pem, "ES256");
again.x === publicKey.x; // true
```

## Rules that hold on every page

**A JWK's `alg` is binding.** When a key says `"alg": "ES256"`, it is used for ES256 and nothing else. Asking for a different algorithm throws `ERR_JWK_INVALID` instead of quietly picking one side ([RFC 7517 §4.4](https://www.rfc-editor.org/rfc/rfc7517#section-4.4)). The single exception is an `oct` key whose `alg` is a content encryption algorithm such as `A256GCM`: that key is a content encryption key, and JWE's `dir` mode consumes it.

**Strings are never keys, except passwords.** A string could be PEM text, a shared secret or a password, and guessing between them is unsafe. `importKey` refuses all strings. PEM goes through [`importPEM()`](/jwk/pem), a secret becomes an `oct` JWK or a `Uint8Array`, and a password goes to [PBES2](/jwk/password).

**Every failure is a `JWTError`.** Each one carries a `code` such as `ERR_JWK_INVALID`, `ERR_JWK_UNSUPPORTED`, `ERR_JWK_KEY_NOT_FOUND` or `ERR_INVALID_OPTION`. Check it with `isJWTError(err, code)`. The full list is on the [errors page](/errors).
