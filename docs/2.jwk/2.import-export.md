# importKey() / exportJWK()

> `importKey` turns whatever key material you hold into what Web Crypto can use. `exportJWK` turns an extractable `CryptoKey` back into a JWK.

```ts
import { generateJWK, importKey, exportJWK } from "unjwt/jwk";

const { publicKey } = await generateJWK("ES256");

const cryptoKey = await importKey(publicKey);
// CryptoKey { type: "public", algorithm: { name: "ECDSA", namedCurve: "P-256" }, usages: ["verify"] }

const jwk = await exportJWK(cryptoKey, { kid: "ec-2026", use: "sig" });
// { kty: "EC", x: "FIs3_F7c…", y: "CbYddHLl…", crv: "P-256", kid: "ec-2026", use: "sig" }
```

You rarely need `importKey` yourself: [`sign()`](/jwt/jws/sign), [`verify()`](/jwt/jws/verify), [`encrypt()`](/jwt/jwe/encrypt) and [`decrypt()`](/jwt/jwe/decrypt) call it on every key you pass. Call it directly to check a key early, to pin its intent with `expect`, or to get a `CryptoKey` for your own Web Crypto code.

## Signatures

```ts
function importKey(
  key: CryptoKey | JWK | Uint8Array,
  options?:
    | JWKAlgorithm // shorthand for { alg }
    | { alg?: JWKAlgorithm; expect?: "public" | "private"; extractable?: boolean },
): Promise<CryptoKey | Uint8Array>;

function importKey(
  key: JWK_oct,
  options: {
    asCryptoKey: true;
    algorithm: AlgorithmIdentifier;
    usage: KeyUsage[];
    extractable?: boolean;
  },
): Promise<CryptoKey>;

function exportJWK<T extends JWK = JWK>(
  key: CryptoKey,
  jwkParams?: {
    "kid"?: string;
    "use"?: string;
    "x5c"?: string[];
    "x5t"?: string;
    "x5t#S256"?: string;
    "x5u"?: string;
  },
): Promise<T>;
```

## Options

| Option               | Type                    | Default                                     | What it does                                                                                                                       |
| -------------------- | ----------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `alg`                | `string`                | the JWK's own `alg`                         | The algorithm to import under. Required for an RSA, EC or OKP JWK without `alg`. Must equal the JWK's `alg` when both are present. |
| `expect`             | `"public" \| "private"` | none                                        | Refuse the other half of a pair before importing. No effect on `oct` keys.                                                         |
| `extractable`        | `boolean`               | `false` for private keys, `true` for public | Asymmetric keys only. A JWK's `ext: false` can lower it, never raise it.                                                           |
| `asCryptoKey`        | `true`                  | none                                        | `oct` JWK only. Import the secret as a `CryptoKey` under `algorithm` and `usage` instead of returning bytes.                       |
| `algorithm`, `usage` | Web Crypto params       | none                                        | Required with `asCryptoKey`.                                                                                                       |

## What each input becomes

| Input                              | Result                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------ |
| `Uint8Array`                       | Returned unchanged.                                                                  |
| `CryptoKey`                        | Returned unchanged, after the `expect` check.                                        |
| `oct` JWK                          | The decoded `k` bytes as a `Uint8Array`, after a length check against the algorithm. |
| `oct` JWK with `asCryptoKey: true` | A `CryptoKey`, non-extractable unless you pass `extractable: true`.                  |
| RSA, EC or OKP JWK                 | A `CryptoKey` under the JWK's `alg` (or the `alg` option).                           |
| `string`                           | Throws `ERR_JWK_INVALID`.                                                            |

The return type follows the input: `ImportedKey<typeof key>` maps bytes and `oct` JWKs to `Uint8Array<ArrayBuffer>`, a `CryptoKey` or asymmetric JWK to `CryptoKey`, and a broad `JWK` to the union of both.

```ts
import { generateJWK, generateKey, importKey } from "unjwt/jwk";

const secret = await generateJWK("HS256");
await importKey(secret); // Uint8Array(64)

const raw = new Uint8Array(32);
(await importKey(raw)) === raw; // true

const handle = await generateKey("HS256");
(await importKey(handle)) === handle; // true

const hmac = await importKey(secret, {
  asCryptoKey: true,
  algorithm: { name: "HMAC", hash: "SHA-256" },
  usage: ["sign"],
});
// CryptoKey { type: "secret", algorithm: { name: "HMAC", hash: { name: "SHA-256" }, length: 512 }, extractable: false }
```

### Why strings are refused

A string could be PEM text, a shared secret or a password. Treating PEM armour as an HMAC secret is a known way to forge tokens, so `importKey` does not guess:

```ts
await importKey("my-secret");
// JWTError ERR_JWK_INVALID: Key must be a JWK, CryptoKey or Uint8Array, not a string.
```

PEM text goes to [`importPEM()`](/jwk/pem). A shared secret becomes an `oct` JWK (from [`generateJWK("HS256")`](/jwk/generate)) or a `Uint8Array`. A password goes to [`deriveJWKFromPassword()`](/jwk/password), or straight into `encrypt()` and `decrypt()`, where PBES2 is the one place JOSE accepts a string as key material.

## The JWK's `alg` is authoritative

A JWK that declares `alg` is imported under that algorithm and no other ([RFC 7517 §4.4](https://www.rfc-editor.org/rfc/rfc7517#section-4.4)). An RSA, EC or OKP JWK without `alg` needs the hint.

```ts
await importKey(publicKey, { alg: "ES384" });
// JWTError ERR_JWK_INVALID: JWK "alg" is "ES256" but the operation requires "ES384".

const { alg, kid, ...noAlg } = publicKey;
await importKey(noAlg);
// JWTError ERR_JWK_INVALID: Algorithm must be provided when importing non-oct JWK
await importKey(noAlg, "ES256"); // CryptoKey { type: "public", … }
```

One exception exists. An `oct` JWK whose `alg` is a content encryption algorithm (`A256GCM`, `A128CBC-HS256`, …) is a content encryption key, and imports under `"dir"`.

For EC and OKP keys the JWK's `crv` picks the curve, and it must match the algorithm. `Ed448` and `X448` are not supported.

## Symmetric and asymmetric keys

An `oct` key's length is checked against the algorithm at import: `HS256`, `HS384` and `HS512` need at least 32, 48 and 64 bytes ([RFC 7518 §3.2](https://www.rfc-editor.org/rfc/rfc7518#section-3.2)), and the AES algorithms need their exact size.

```ts
await importKey({ kty: "oct", k: "c2hvcnQ", alg: "HS256" });
// JWTError ERR_JWK_INVALID: HS256 requires a key of at least 32 bytes (got 5)
```

An asymmetric JWK's `key_ops` narrows what the imported key may do. A `key_ops` that permits none of the usages the algorithm needs is refused before Web Crypto sees it:

```ts
await importKey({ ...publicKey, key_ops: ["encrypt"] });
// JWTError ERR_JWK_INVALID: JWK "key_ops" does not permit verify.
```

## Checking intent with `expect`

`expect` catches a key in the wrong place, such as a private key about to be published as a verification key:

```ts
await importKey(someKey, { expect: "public" });
// JWTError ERR_JWK_INVALID: Private JWK passed where a public key is expected.
```

A deployment that stored only the private key alone can still derive it with [`toPublicJWK()`](/jwk/generate#storing-the-private-key-alone).

`verify()` and `encrypt()` pass `expect: "public"`, and `sign()` and `decrypt()` pass `expect: "private"`, so the high-level calls are already checked.

## exportJWK()

`exportJWK` reads an extractable `CryptoKey` back into a JWK. Web Crypto's `ext` and `key_ops` describe the `CryptoKey`, not the key, so they are not written: an import grants the usages `alg` allows and decides extractability itself. `jwkParams` decorates the result; it cannot redescribe the key, so `alg`, `kty`, `key_ops`, `ext` and key-material members throw `ERR_INVALID_OPTION`.

The `alg` on the result is whatever Web Crypto writes. Web Crypto omits `alg` for EC and OKP keys, and labels an AES-GCM key `A*GCM` even when it was generated for `A*GCMKW`. When the label matters, generate with [`generateJWK()`](/jwk/generate), which stamps the algorithm you asked for.

A `CryptoKey` does not tell the compiler its key type. Narrow it with the type parameter when you know it:

```ts
import { exportJWK, generateKey } from "unjwt/jwk";
import type { JWK_RSA_Public } from "unjwt/jwk";

const pair = await generateKey("RS256");
const pub = await exportJWK<JWK_RSA_Public>(pair.publicKey);
pub.e; // "AQAB"
pub.alg; // "RS256"
```

## Non-extractable keys

A private key imported from a JWK is non-extractable by default. It can sign or decrypt, but `exportJWK` refuses it:

```ts
const signer = await importKey(privateKey); // extractable: false
await exportJWK(signer);
// JWTError ERR_JWK_INVALID: A non-extractable CryptoKey cannot be exported as a JWK.
```

Pass `{ extractable: true }` to `importKey` when you need to export it later.

## Errors

| Cause                                                                                   | `code`               |
| --------------------------------------------------------------------------------------- | -------------------- |
| A string key                                                                            | `ERR_JWK_INVALID`    |
| An asymmetric JWK with no `alg` and no hint                                             | `ERR_JWK_INVALID`    |
| A requested `alg` that differs from the JWK's                                           | `ERR_JWK_INVALID`    |
| An `oct` key too short or the wrong size for its algorithm                              | `ERR_JWK_INVALID`    |
| A `crv` or `key_ops` the algorithm cannot use                                           | `ERR_JWK_INVALID`    |
| The wrong pair half under `expect`                                                      | `ERR_JWK_INVALID`    |
| `asCryptoKey` without `algorithm` and `usage`                                           | `ERR_JWK_INVALID`    |
| `exportJWK` on a non-extractable key                                                    | `ERR_JWK_INVALID`    |
| `exportJWK` on something that is not a `CryptoKey`, or a reserved member in `jwkParams` | `ERR_INVALID_OPTION` |
