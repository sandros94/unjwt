# Sessions on h3

> Sign users in with a signed session cookie on h3, read it on every request, and guard a group of routes with one middleware.

An h3 event already has the shape a session reads: the incoming `Request` on `event.req`, the response headers on `event.res`, and a `context` that lives for one request. So you hand the event to the session as it is, with no adapter in between. The session is a JWS, a token with a signature across it: the server can tell whether it wrote the cookie, and anyone holding the cookie can read what's inside. [Concepts](/getting-started/concepts) has the vocabulary.

## Before you start

- Install both packages:

  ```sh
  pnpm add h3 unjwt
  ```

- A session key that survives restarts. Generate it once, in your project folder:

  ```sh
  node --input-type=module -e 'import { generateJWK } from "unjwt/jwk"; console.log(JSON.stringify(await generateJWK("HS256")))'
  ```

  It prints one line of JSON, `{"alg":"HS256","kty":"oct","k":"…","kid":"…"}`. Store that whole line as `SESSION_KEY` in your secret manager, or in a `.env` file you never commit and load with `node --env-file=.env`. Whoever holds it can sign a session for any user. Replacing it signs everyone out.

- HTTPS, or `localhost` while you develop. The cookie is called `__Host-unjwt-jws` and carries `Secure`, so a browser drops it on plain HTTP anywhere else.

## Sign users in and out

The app reads the key at start-up, defines the session once, and opens it in each route with `appSession.use(event)`:

<!-- automd:region src="../../examples/recipes/h3.ts" -->

```ts [h3.ts]
import { H3, HTTPError, readBody } from "h3";
import { defineJWSSession } from "unjwt/session";

const SESSION_KEY = process.env.SESSION_KEY;
if (!SESSION_KEY) throw new Error("SESSION_KEY is not set");

const appSession = defineJWSSession<{ user: string }, "1h">({
  key: JSON.parse(SESSION_KEY),
  maxAge: "1h",
  rolling: "15m",
});

export const app: H3 = new H3()
  .post("/login", async (event) => {
    const body = await readBody<{ user?: unknown }>(event);
    if (typeof body?.user !== "string") {
      throw new HTTPError({ status: 400, message: "user required" });
    }
    const session = await appSession.use(event);
    await session.update({ user: body.user });
    return { user: session.data.user };
  })
  .get("/me", async (event) => {
    const session = await appSession.use(event);
    if (!session.id) throw new HTTPError({ status: 401, message: "Sign in first" });
    return session.data;
  })
  .post("/logout", async (event) => {
    const session = await appSession.use(event);
    await session.clear();
    return { ok: true };
  });
```

<!-- /automd -->

Start it with `serve(app)` from `h3`, or hand `app.fetch` to any runtime that takes a fetch handler. What each part does:

- **Start-up check**: without `SESSION_KEY` the module throws before the server listens, so a forgotten variable stops the deploy instead of the first sign-in.
- **The event as it is**: `use(event)` reads the cookie from `event.req` and writes `Set-Cookie` onto `event.res`, so the cookie leaves with whatever the route returns.
- **No session yet**: `session.id` stays `undefined` until `update()` signs a first token. That's the check `/me` makes, and reading alone never sets a cookie.
- **Lifetime**: `maxAge: "1h"` ends a token an hour after it was signed. `rolling: "15m"` signs a fresh hour on the first request that finds the token at least 15 minutes old, so an active user stays in and an idle one is out 45 to 60 minutes after their last request.
- **Readable data**: the cookie is `HttpOnly`, so page scripts can't read it, but the user can decode it. Keep secrets out of `update()`, or use a JWE session (see Going further).
- **Sign out**: `clear()` sends the cookie back with `Max-Age=0`, and the browser deletes it.

## Guard a group of routes

An h3 middleware sees the same event as the route after it, and the session keeps its state on `event.context`. A middleware can therefore refuse a request without a session, and the route opens the same session again without a second read:

<!-- automd:region src="../../examples/recipes/h3.ts" name="middleware" -->

```ts [h3.ts]
app.use("/account/**", async (event) => {
  const session = await appSession.use(event);
  if (!session.id) throw new HTTPError({ status: 401, message: "Sign in first" });
});

app.get("/account/profile", async (event) => {
  // Same event, same session: the middleware's read is reused
  const session = await appSession.use(event);
  return { user: session.data.user, expiresAt: session.expiresAt };
});
```

<!-- /automd -->

- **One read per request**: the second `use(event)` returns the session the middleware opened. The token is verified once, and the [`onRead` hook](/sessions/hooks) fires once.
- **Returning nothing continues**: a middleware that returns `undefined` hands the request on; the thrown `HTTPError` ends it with a 401 before the route runs.

## When it fails

| Situation                                            | What happens                                                                                                                        |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `SESSION_KEY` unset or empty                         | The module throws `SESSION_KEY is not set` at start-up.                                                                             |
| `SESSION_KEY` is not JSON                            | `JSON.parse` throws a `SyntaxError` at start-up. Store the line `generateJWK` printed, quotes included.                             |
| JSON that is not a signing key, such as a public JWK | `defineJWSSession` throws `ERR_SESSION_KEY_INVALID` at start-up, and the server doesn't start. See [Handle errors](/safety/errors). |
| An `HS256` JWK whose `k` doesn't decode              | Every request that opens the session answers 500: `use()` throws `ERR_SESSION_KEY_INVALID`.                                         |
| Plain HTTP on a host other than `localhost`          | `/login` answers 200 with the cookie, the browser refuses a `Secure` cookie over HTTP, and `/me` stays 401. Serve over HTTPS.       |
| Request without the cookie                           | `session.id` is `undefined`, so `/me` and every `/account/**` route answer 401.                                                     |
| Token older than `maxAge`                            | The session opens empty, `/me` answers 401, and the response drops the cookie. The [`onExpire` hook](/sessions/hooks) fires.        |
| Cookie signed with another key, or changed by hand   | Same 401 and cookie drop. The `onError` hook gets `ERR_SESSION_TOKEN_INVALID`; nothing is thrown from `use()`.                      |
| `/login` without a `user` string                     | 400, and no cookie is set.                                                                                                          |

## Going further

- **Hide the data**: `defineJWESession` encrypts the token, so the user can't read it either. It takes an `oct` key such as `generateJWK("A256GCM")`; see [Configure a session](/sessions/configure).
- **API clients**: set `sessionHeader` to read a bearer token from a header before the cookie, for clients that don't keep cookies. See [Configure a session](/sessions/configure).
- **Revocation and audit**: hooks run when a session is read, updated, cleared or expires. See [Hooks](/sessions/hooks).
- **Every route the same way**: the [Nitro](/examples/nitro) recipe runs this flow with one file per route and a WebSocket on top.
