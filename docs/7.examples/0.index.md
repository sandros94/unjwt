# Recipes

> Whole apps rather than single functions: one session flow on each framework, with the key, the routes and what goes wrong.

Every session recipe builds the same three routes, so you can put two frameworks side by side and see only what differs. `POST /login` takes `{ "user": "…" }` and starts a session, `GET /me` answers with the session's data or a 401, and `POST /logout` ends it. Each recipe then adds the one thing its framework does its own way. The session itself is a signed cookie; the [Sessions](/sessions) section explains every option the recipes leave at its default.
